# Разовые скрипты над данными

Здесь лежат скрипты, которые меняют ДАННЫЕ, а не схему: переименования,
разовые исправления, аварийные действия по раннбуку.

Почему не в `supabase/migrations/`: миграции описывают строение базы и
применяются к любой копии проекта, в том числе к чистой. Разовое действие над
конкретными строками к чистой базе применять бессмысленно, а попав в общий
пакет — выполнится ещё раз там, где не нужно.

Правила для файлов в этом каталоге:

- одна транзакция, все проверки ДО первой записи;
- идемпотентность: повторный запуск либо ничего не меняет, либо честно
  сообщает об этом;
- сообщения об ошибках по-русски и по делу — их читает владелец, а не
  разработчик;
- первым шагом — запрос «что есть сейчас», последним — «что стало»;
- никаких подставленных логинов и идентификаторов: только плейсхолдеры
  с объяснением, где взять значение.
