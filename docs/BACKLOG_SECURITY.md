## Раунд 2 (2026-07-30, v205) — закрыто

- [x] **HIGH: гонка `dirty`.** Push делал снимок `rows`, дальше десятки await (чанки по 100; на 3000
      позиций — десятки секунд) и в конце БЕЗУСЛОВНО снимал dirty. Правка, сделанная пользователем
      в это окно, в снимок не попадала; если следующий push падал по сети, retry не запускался
      (он смотрит на dirty), а очередной pull затирал правку облачными данными — молча.
      Введён `markDirty()` со счётчиком поколения `_dirtyGen`: dirty снимается только если поколение
      не изменилось, иначе планируется добивочный проход.
- [x] **HIGH: наложение двух push залипало `cloud.busy`.** Сохранение/восстановление `_outerBusy`
      при пересечении оставляло `busy=true` навсегда → realtime-pull и активация базы мертвы
      до перезапуска. Добавлен guard `cloud._pushing` (второй вызов ставит `pushPending` и выходит).
- [x] **HIGH: обработчик `storage` подхватывал сессию ДРУГОГО пользователя** (не было сверки `user.id`).
      На общем телефоне вход второго человека в другой вкладке заставлял первую взять его токен,
      продолжая держать данные и задачи первого → выгрузка уходила в чужой аккаунт (`owner_id` нового
      пользователя). Теперь подхватываем только ротацию того же `user.id`.
- [x] **HIGH: `purgeCloudProfiles` не удалял КОПИИ облачной базы.** Копии создаются при конфликте
      «телефон vs общая база», при view-only бэкапе и перед сменой роли, но не имели `cloudId` →
      попадали в `locals` и оставались на устройстве: следующий вошедший видел их в списке баз,
      открывал и правил чужой склад, а «Экспорт всех баз» выгружал его в файл.
      Копии помечаются `fromCloudId` и чистятся вместе с облачными (слот + sig-ключи).
- [x] **HIGH: JSON-бэкап был ложным** — содержал максимум 500 записей журнала на вид (локальный журнал
      урезан на pull), при этом «Все базы» подписан как «главный страховочный бэкап».
      `exportData` тянет ПОЛНЫЙ архив движений из облака (`fullCloudJournals`) и честно предупреждает,
      если история неполная; «Все базы» помечает файл `journalsMayBeTruncated` + тост.
- [x] **HIGH: залипание после пересменки.** `handover_shift` переписывает `owner_id` задач на
      заступающего, наш upsert по тем же id упирается в RLS 403 → бесконечный ретрай раз в 6 с,
      а `TASKS_DIRTY` блокировал ЛЮБОЙ pull → устройство навсегда показывало переданные задачи.
      При отказе прав (или 5 неудачах подряд) приоритет облаку: снимаем dirty, сбрасываем подпись,
      тянем актуальный список, сообщаем пользователю.
