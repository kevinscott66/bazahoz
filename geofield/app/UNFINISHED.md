# Реестр незавершённого

Барьер заглушек (`geofield-agent-build.md` §5) допускает недоделанное **только**
за выключенным feature-флагом и **только** с записью здесь. Всё остальное — стоп
перед вливанием.

| Что | Где | Флаг | Почему отложено |
|---|---|---|---|
| Транспорт печати на bluetooth-принтер этикеток | `lib/screens/sample_capture_screen.dart` `_onPrint` | `AppFeatures.bluetoothLabelPrinter` (выкл.) | Нужен SDK конкретного полевого принтера + железо. Рендер бирки (QR+номер+цвет типа) — настоящий; при выключенном флаге UI честно сообщает «принтер не подключён», а не имитирует успех. Протокол принтера — открытый вопрос ТЗ р.14. |
| Снятие координат с GPS-приёмника | `lib/screens/point_form_screen.dart` `_onGps` | `AppFeatures.gpsCapture` (выкл.) | Нужен плагин геолокации + разрешения платформы + реальное устройство. Основной путь пока — ручной ввод (валидный по схеме: `coord_source='manual'`). Кнопка честно сообщает о недоступности. |
| «Снять с датчика» для структурных замеров | `lib/screens/point_form_screen.dart` `_onSensor` | `AppFeatures.sensorCompass` (выкл.) | Нужен плагин магнитометра/акселерометра + устройство. Ручной ввод азимута/угла работает полностью, с валидацией диапазонов. |

## Перф-бэклог (первый прогон perf-auditor; чинить по замерам на устройстве)

Исправлено сразу: виртуализация журнала (ListView.builder), индексы
route_id/project_id/measurements(parent)/change_log(entity), параллельная
загрузка справочников формы. Остальное — требует замеров, не только чтения кода:

- `pendingWireSize` сериализует весь бэклог ради цифры на экране; пакетайзер
  держит все пакеты в памяти. При целевых «сотнях КБ» — в бюджете; замерить
  при неделях офлайна (тысячи мутаций), при необходимости — потоково.
- Автосейв с паузами >400мс даёт по мутации на паузу (дельта мала, но число
  строк change_log на точку при «перчаточном» темпе ввода не оценено) —
  замерить в поле; возможное решение — склейка подряд идущих дельт одного поля.
- `change_log` и `record_history` не архивируются — рост файла БД за сезон
  замерить; план: усечение synced=1 после подтверждённого бэкапа камералки.
- Холодный старт <2с и «карта открыта <250МБ» — замер на слабом устройстве;
  карта ещё не реализована, GPS-бюджет (<12%/час) проверять при подключении
  плагина геолокации.

- Смена привязки пробы к другой точке/интервалу — показана как read-only. Пикер — этап 1, бэклог.
- Фото (ТЗ §6.6) — блок не показан вовсе (нет кнопки-обманки): камера и очередь фото — следующий инкремент этапа 1.
- Минерализация чек-боксами (ТЗ §6.3) — пока свободное поле «примечание»; чек-боксы появятся вместе со справочником минералов (нужна ревизия консультанта).
- Переходы статуса пробы (упакована/отправлена) — отдельное действие камералки/ведомости, не экран регистрации; правка полей статус не трогает.
- Смена системы координат на лету (ТЗ §6.2) — ввод пока в WGS-84; пересчёт СК-42/МСК — вместе с proj4-библиотекой.
- Объём (л) и масса шлиха (г) для шлиховой пробы; сечение борозды — нужны колонки в схеме и решение консультанта (geofield-domain-review.md, вопрос 1).
- Магнитный vs истинный азимут и поправка на склонение — нужен флаг уровня проекта (domain-review, вопрос 4).
- Интенсивность минерализации (ТЗ §6.3 «поле интенсивности») — пока только выбор минералов чек-чипами; интенсивность — после решения по справочнику.
- Справочники цвета и зернистости — пока свободный текст (domain-review, «Важное»).
- Синхронизация: сжатие gzip (zstd из протокола §7 — позже, вместе с relay); отдельной фото-очереди на экране синхронизации нет, потому что фото ещё не реализованы; экспоненциальный откат между сеансами — за пользователем (кнопка), автоповтора нет намеренно (связь — событие, ТЗ 6.8).
- ~~LWW без настоящего HLC~~ — **закрыто:** реализован HLC (`sync/hlc.dart`): физвремя+счётчик+device_id сортируемой строкой, подтягивание при приёме, детерминированная ничья; LWW сравнивает `row_clocks` (HLC последнего писателя строки), не `modified_at`. Остаток: мутации со старым ISO-форматом `logical_ts` (если такие базы существуют) при PULL уходят в conflicts на разбор, а не применяются — прототипные базы пересоздаются, миграция меток не делалась намеренно.
- Полная схема БД — прототип поднимает подмножество (`projects`, `samples`, `change_log`); канон — `geofield/core/schema/001_initial.sql`.
- **Аварийный выход при неисправном хранилище.** Экран сбора пробы намеренно не
  закрывается, если запись валидных данных провалилась (диск полон / залочен WAL),
  и показывает ошибку — чтобы не потерять данные молча (ТЗ §0.2). Пути «Готово»,
  «назад» и «Удалить» обрабатывают сбой симметрично. Но при действительно
  неисправном устройстве геолог может застрять на экране. Прод (этап 1, hardening):
  «сохранить в аварийную очередь и выйти» + диагностика хранилища.
