# Реестр незавершённого

Барьер заглушек (`geofield-agent-build.md` §5) допускает недоделанное **только**
за выключенным feature-флагом и **только** с записью здесь. Всё остальное — стоп
перед вливанием.

| Что | Где | Флаг | Почему отложено |
|---|---|---|---|
| Транспорт печати на bluetooth-принтер этикеток | `lib/screens/sample_capture_screen.dart` `_onPrint` | `AppFeatures.bluetoothLabelPrinter` (выкл.) | Нужен SDK конкретного полевого принтера + железо. Рендер бирки (QR+номер+цвет типа) — настоящий; при выключенном флаге UI честно сообщает «принтер не подключён», а не имитирует успех. Протокол принтера — открытый вопрос ТЗ р.14. |
| «Снять с датчика» для структурных замеров | `lib/screens/point_form_screen.dart` `_onSensor` | `AppFeatures.sensorCompass` (выкл.) | Нужен плагин магнитометра/акселерометра + устройство. Ручной ввод азимута/угла работает полностью, с валидацией диапазонов. |

## Безопасность — блокеры этапов (аудит безопасности, не откладывать «на потом»)

- **База вынесена из Documents в Application Support** (закрыто в этом заходе):
  Info.plist включает file sharing ради выгрузок CSV/фото, а `getDatabasesPath()`
  на iOS — это Documents; держать там `geofield.db` означало отдать весь SQLite
  на копирование через «Файлы»/Finder. База переехала в Application Support (вне
  file sharing), сборки 1–5 мигрируются переносом файла + WAL/SHM. В Documents
  остаются только выгрузки CSV и фото (их пользователь и должен доставать).
  Остаток — шифрование самого файла (ниже).
- **Шифрование данных на устройстве — блокер этапа 1 (прод).** Мастер-план §7
  требует шифрования локальной БД; сейчас SQLite лежит открытым файлом, а
  `relay_token` — строкой в `sync_state`. Телефон теряется в поле, данные по
  недрам — чувствительные (мастер-план §13). Прод: `flutter_secure_storage`
  для токена + SQLCipher (или EncryptedSharedPreferences-ключ к базе).
- **Общий токен и самоназванный device_id — блокер этапа 5 (мультипартия).**
  Один Bearer-токен на всех: нельзя отозвать одно устройство, не поменяв
  секрет всем; `device_id`/`author_id` relay принимает на веру — подделка
  атрибуции тривиальна. Этап 5: токен на устройство (или mTLS) + привязка
  device_id к токену на relay.
- **TLS перед relay — обязателен в проде** (см. `../relay/README.md`, раздел
  «TLS»): relay слушает plain HTTP, терминатор (Caddy/nginx/WireGuard) ставит
  оператор. Клиент требует https и пускает http только на localhost.
- Опционально (укрепление CI): пин GitHub Actions по SHA вместо мажорных тегов.

## Перф-бэклог (первый прогон perf-auditor; чинить по замерам на устройстве)

Исправлено сразу: виртуализация журнала (ListView.builder), индексы
route_id/project_id/measurements(parent)/change_log(entity), параллельная
загрузка справочников формы. Остальное — требует замеров, не только чтения кода:

- `pendingWireSize` сериализует весь бэклог ради цифры на экране; пакетайзер
  держит все пакеты в памяти. При целевых «сотнях КБ» — в бюджете; замерить
  при неделях офлайна (тысячи мутаций), при необходимости — потоково.
- ~~Автосейв даёт по мутации на паузу~~ — **закрыто:** logChange склеивает
  неотправленные мутации записи (insert+update → insert, update+update →
  один update), умерший до синхронизации черновик исчезает без tombstone;
  миграция v3 компактирует старые бэклоги.
- `change_log` и `record_history` не архивируются — рост файла БД за сезон
  замерить; план: усечение synced=1 после подтверждённого бэкапа камералки.
- Холодный старт <2с и «карта открыта <250МБ» — замер на слабом устройстве;
  карта ещё не реализована, GPS-бюджет (<12%/час) проверять при подключении
  плагина геолокации.

- **Аварийный выход при неисправном хранилище.** Экран сбора пробы намеренно не

  «сохранить в аварийную очередь и выйти» + диагностика хранилища.
