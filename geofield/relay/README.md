# GeoField relay — точка приёма дельта-синхронизации

Реализация relay-узла из `../core/sync-protocol.md` §2–3 (ТЗ §1.4): один
Go-бинарь без зависимостей, мало памяти. Принимает пакеты мутаций от полевых
устройств, дедуплицирует по `change_id`, отдаёт чужие мутации по курсору.

## Запуск

```bash
RELAY_TOKEN=<секрет> go run . -addr :8080 -data relay-journal.jsonl
# или бинарь:
go build -o relay . && RELAY_TOKEN=<секрет> ./relay
```

Без `RELAY_TOKEN` сервис **не стартует** — молчаливо-открытый relay в интернете
означал бы утечку данных по недрам (мастер-план §7).

## API

Все запросы — `Authorization: Bearer <RELAY_TOKEN>`.

### `POST /v1/push` — пакет мутаций от устройства
Тело (можно `Content-Encoding: gzip`, лимит 8 МиБ):
```json
{"device_id":"dev-a","changes":[
  {"change_id":"…","entity_table":"samples","entity_id":"…",
   "op":"insert|update|delete","payload":{…},"author_id":"…","logical_ts":"…"}
]}
```
Ответ: `{"batch_id":"b_…","accepted":[…],"duplicates":[…],"last_seq":N}`.

Гарантии (§8 протокола):
- **идемпотентность** — повторная доставка пакета безопасна, дубликаты
  перечисляются отдельно и не пишутся второй раз;
- **атомарность пакета** — одна невалидная мутация → 422 и пакет отвергнут
  целиком (клиенту проще возобновиться, чем сшивать частичный приём);
- **durability** — пакет пишется одним append с fsync; оборванная падением
  последняя строка отбрасывается реплеем при старте.

### `GET /v1/pull?device_id=…&cursor=N&limit=M` — чужие мутации после курсора
Ответ: `{"changes":[…],"next_cursor":N,"has_more":bool}`.
`next_cursor` — seq последней *просмотренной* записи (свои мутации
пропускаются, но двигают курсор). Возобновление — просто передать курсор.

### `GET /healthz`
`{"ok":true,"last_seq":N}` — без авторизации, для мониторинга.

## Хранилище

Append-only JSONL-журнал + индекс в памяти (реплей при старте). Для партии в
несколько человек и сеансов в сотни КБ этого достаточно и это честно durable.

## Дальше (не реализовано, зафиксировано)

- **Проталкивание в Postgres камералки** через обратный туннель (WireGuard) —
  следующий шаг этапа 2; сейчас мутации остаются в журнале relay.
- **zstd** поверх gzip (протокол §7) — когда клиент научится.
- Ротация/компакция журнала; метрики.

## Тесты

```bash
go vet ./... && go test -race ./...
```
Покрыто: идемпотентность повторного пакета, исключение собственных мутаций и
возобновление по курсору, пагинация, реплей после рестарта с оборванным
хвостом, авторизация, gzip, атомарный отказ битого пакета, битый JSON.
